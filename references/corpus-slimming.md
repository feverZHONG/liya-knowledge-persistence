### F29 · 语料长胖了做减法：先只读审计、再落刀；账／副本／可归档三分（2026-09-20

29. **语料长胖了做减法：先只读审计、再落刀；账／副本／可归档三分（2026-09-20 长篇项目账＋skill 两轮实证）** — 触发：一个语料（技能库、项目账、过程稿）堆了几十份、涨到十几万字节，用户说「同步整理」「好好沉淀一下」。


### F29a · 先审计后落刀

- **先审计后落刀**：审计四栏——① **重复清单**（`文件:行号`＋两边逐字原文＋「留谁／其余改成一行指向」）② **过期清单**（旧口径数值、已作废红线、已完成的一次性记录）③ **体量体检**（每份 KB/行数＋体量/信息比最差的几份）④ **不可砍清单**。落刀时每条改动**对应审计编号**，审计没列的**不动**；拿不准的不动并写进回报。


### F29b · 复核手段两条

- **复核手段两条**：grep 旧值应 **0 命中**（如旧带数字、作废红线）；「**单点存放**」核验（带值只在 `gate.json`、手法卡只在 craft-library、三张参数表只在 gate.md——其余均为指向）。


### F29c · 三分类

- **三分类**：① **账**（落地记录、核对档的历史结论、现行参数表、大纲）一个字不动；② **副本**（同一事实的第二处、第二份节表）→ 按第 25 条「一件东西一『家』」留唯一的家、其余改一行指向；③ **可归档**（一次性、已完成、只对当时有用）→ 挪进 `归档-YYYY-MM/`＋标「历史，勿照它开工」，**迁不删**。


### F29d · 🔴 反规则：「反正 git 里有」不是删账的理由

- **🔴 反规则：「反正 git 里有」不是删账的理由**——判据是「后来的人照着它干活会不会出错」，不是「能不能从历史里挖回来」；账要能**不用考古就读到**。顺手删旧副本前先把「账／副本／可归档」分清。


### F29e · 现状句不是历史记录，是「当下状态」的断言

- **现状句不是历史记录，是「当下状态」的断言**——最危险的假账形态是**比现实乐观**（「已清零」「还剩一节挂账」而工具实测 8 节在挂；注记与自己的数据打架）。规矩：现状句（挂账数／进度／「待换版」）每轮开工先拿工具重测，与工具不符当场改口；**同一组数字只留一个正本**（带值＝项目 `gate.json`，总账／节表＝实测）。

### F29g · 「自有 skill」与「自动保养」是两套闸门，别把两件事混成一件事

- ⚠️ **「自有 skill」与「自动保养」是两套闸门，别把两件事混成一件事**（两条实测，都在同一轮里碰到）：**前台**改动（会话内、用户在场时）对自有 skill 照常生效；但**后台／自动策展**的写入会被拒（`Refusing background curator patch … not curator-managed (created_by=None)`）——所以「自动改会被拒」与「永不被自动置 stale／归档」**两句话都对**，说的是两个不同的动作，别因为后者成立就推断前者不存在（本文件里 日记类 skill（作者环境，未单独公开）／记录类 skill（作者环境）／某作品档案库 三处早就是这么记的）。想让它能被自动维护：`hermes curator adopt <name>`——adopt 后才有 stale／archive 生命周期，要留就把 `pin` 一起用。教训：凡「某个工具／开关会拦住你／不会拦你」这类结论，**先跑一次看真实输出**（各自跑一遭 + `hermes curator status` 两段都读全），再落笔。


### F29h · 快手（2026-09-20 立）

- 🧰 **快手（2026-09-20 立）**：`bin/tidy` —— `scan <目录>`（盘点：编号诊断／体量／疑似重复段落／过期词／断链数）｜`dup`（只找重复段落）｜`stale`（只扫过期关键词，词表可放目标目录 `.tidy-stale-words`）｜`single <值> <目录>`（「单点存放」核验）｜`links <目录> [--fix]`（断链，包装 md-link-maintenance）。审计四栗的机械底稿一条命令出；**判读（留谁／改指向／归档）仍靠人**。
