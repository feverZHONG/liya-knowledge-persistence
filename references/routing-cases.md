# 落位判例 · 一条信息／素材该放哪（纪律 5／6／8–13／17／25／28）

> 2026-09-22 从 SKILL.md 拆出（**内容一条未删，逐字搬运**）。SKILL.md「纪律」只留每条可执行的那一句 + 标签；本文件是该条背后的判例、反例、实测数字与完整流程。

### A5 · skill 资产登记（2026-08-15 用户拍板）

5. **skill 资产登记（2026-08-15 用户拍板）** — 往 skill 新增任何资产（脚本/参考/模板/文件）必须在 **SKILL.md 里登记**（引用行/脚本清单段），不只写进 references 内部——SKILL.md 是入口，资产清单要一眼可见


### A6 · git跟踪意识（含备份盲区）

6. **git跟踪意识（含备份盲区）** — 创建跟踪/进度/文档文件前先确认目录是否在 `.gitignore`；被拦的文件不随 push 同步。需要 git 跟踪放 skill 根 PLAN.md 或 SKILL.md。**另一半：被 `.gitignore` 隔离的目录同时也是「`git ls-files` 型备份」的盲区**——每日文字包（`scripts/backup_text.py`）按 `git ls-files` 取文件，里面看不见的东西一整个不进包。所以**新建独立仓库 / 被 ignore 的新目录后，要显式把它登记进备份清单**（该脚本用 `EXTRA_REPOS`：独立仓库单独 `git ls-files` + 前缀 arcname 打包），否则内容只活在远程一处，本地备份看着成功其实没盖住它。判据：`git check-ignore -v <路径>` 命中 = 备份也看不见它。


### A8 · 独立索引文件（2026-08-01 起）

8. **独立索引文件（2026-08-01 起）** — 索引用独立 INDEX.md（`diary/INDEX.md`、`<记忆目录>/INDEX.md`），文件内部不放目录；条目 `日期|标题|摘要|时间`；新增同步更新 INDEX 一行。🔴 **日期红线：INDEX 日期/时间必须与正文署名一致，跨天补记写事件当天**


### A9 · skill 降级为经验（2026-08-10 三次实战）

9. **skill 降级为经验（2026-08-10 三次实战）** — 低频/一次性 skill 不值得独立：核心经验压缩成 `<记忆目录>/{topic}-experience.md`，有复用价值的脚本挪 `<项目目录>/scripts/`，然后删 skill。信号：零使用记录+用户裁决「顶多算经验」+内容会过时。**降级不是丢内容**——经验+脚本归位后才删，pruning-history 登记去向


### A10 · 查询沉淀进对应 skill references，不留杂烩文件（2026-08-

10. **查询沉淀进对应 skill references，不留杂烩文件（2026-08-10 拆 search-history 教训）** — 判断标准：有没有方法论增量（渠道通断/踩坑/钉死的渠道）——有→进对应 skill references；没有→内容本体归档案/资料库。拆杂烩文件时 grep 全库同步引用，并同步改 memory 索引


### A11 · skill 拆分类：知识本体留 skill，一次性事件档案拆 workspace

11. **skill 拆分类：知识本体留 skill，一次性事件档案拆 <档案目录>（2026-08-13 九型实战）** — ① 拆前确认外部零引用；② `git mv`；③ 修内部相对路径；④ 目标目录建 INDEX.md + SKILL.md 加指向行


### A12 · 新 skill 建成后焊触发链路（2026-08-16 read-url 实例）

12. **新 skill 建成后焊触发链路（2026-08-16 read-url 实例）** — 收尾焊三道：① AGENTS.md 锚点加行；② memory 常驻触发句；③ 相关入口 skill 挂引用。平台特化 skill 不必挂，普通入口必挂


### A13 · skill 内部多文件同步维护（2026-08-25）

13. **skill 内部多文件同步维护（2026-08-25）** — 改任何文件对照维护清单过一遍（清单固化在 skill 内部显眼处）；引用路径按实际命名写，别用别名/通配符


### A17 · 通用能力发现不绑单一作品库（2026-09-05 红米文字识别实例）

17. **通用能力发现不绑单一作品库（2026-09-05 红米文字识别实例）** — 通用工具/系统能力发现（不绑特定作品/平台）记 `<记忆目录>/{topic}.md` + INDEX 挂行，或对应**通用** skill references；**作品库 skill 只写该素材来源的一行标注，不展开通用发现**。实例：手机系统「文字识别→文本识别」模式（禁复制页面直读文本层）→ `<记忆目录>/text-recognition.md`；某作品档案库 的故事档来源字段只标「文本识别模式提取」，功能说明不回抄进该 skill


### A25 · 素材归位：一件东西一「家」，混合体裁先分层（2026-09-12 用户「别随便堆

25. **素材归位：一件东西一「家」，混合体裁先分层（2026-09-12 用户「别随便堆内容，记得找出来，拆分到对应的位置」）** — 一批素材进来时先逐件判层，再动手写；用户说「别堆」/「拆到对应位置」时要的是**归位表 + 逐件落对**，不是产出更多文件。四问：① **混合体裁先拆**（实例：官方生日贺图文案＝第三人称旁白＋引号内第一人称原话两层——旁白归登记档只作语境，原话归「一手原话层」并挂链，不重抄）；② **一件东西只放一「家」**——他处只挂链不复制，谁定「原文层」谁就是家；③ **专属 vs 通用**——角色/作品专属的分析件落**作品库**（写作取材处，如速查层），通用 skill 只留方法＋指针（实例：声线锚点表从通用 skill 挪回作品库）；④ **收尾跑全库链接校验**——`md-link-maintenance` 的 `scripts/check_md_links.py`（markdown 链接形态不在反引号 fix 脚本覆盖面内），新写的链接最容易 `../` 层级错。⚠️ 例：`某作品档案库` 为用户自有 skill（自动改被拒）——兽耳侧落位细则（台词库＝一手原话／判据第一人称（旁白不算）／`references/02-组织与拓展法.md` 落位表）已写进作品库文档，但 SKILL.md 层同步被拒；建议 `hermes curator adopt 某作品档案库`。**发布件的「描述」同理（同一原则的延伸）**：一个对外发布的 skill，它的描述会同时投影到 SKILL.md frontmatter／仓库 README／GitHub About（API 设的，**文件里根本没有**）／别的 skill 的转引——收尾先 `grep -rn <skill名> skills/ repos/` 看散在哪，**指定唯一来源文件**（通常一份 `references/scope-and-boundaries.md`：管什么／不管什么／跟邻居 skill 的边界——规则相反的地方要点名），其余一律改成指针；别处临场写的对照/说明没根，迟早互相打架。


### A28 · 准则类信息按通用度分层落位

28. **准则类信息按通用度分层落位** — 新冒出来的**准则/授权/立场**（不是一次事件）别只写进它第一次落地的任务域。按通用度挑层；三层可以都写，但每层写的是**那一层的形态**，不是把细则复制三份：


### A28a · `SOUL.md`（身份层）

- **`SOUL.md`（身份层）** — 长期立场与关系约定（如「自己教用户的事」节）。**门槛最高**：身份文件不喂胖，只加一条短规则，且**先提给用户、点头了才加**。


### A28b · `AGENTS.md`（现场规则层）

- **`AGENTS.md`（现场规则层）** — 每次睁眼都在上下文里的通用准则；放这儿的理由就是漏不掉。一条短节 + 一行指向细则。


### A28c · 任务域 skill

- **任务域 skill** — SKILL.md 触发词（下次进得来）+ `references/` 细则（查得到、下得去手）。


### A28d · 要的是抽出来的那层准则，不是细则复制三份

判据：这条规矩换个场景还成立吗？成立 → 往上提一层，别让它烂在某个任务域里。用户说「别的地方也要写一下」「要记的东西自然是更通用的思路」就是这个信号——**要的是抽出来的那层准则，不是细则复制三份**。
