# 长案卷分层归档（一案一档，越查越厚时）

> 适用：`workspace/records/` 下的**多阶段调查案件**（追踪一个事件/对象，一轮轮加料，长到几十 KB）。
> 与 `archive-pattern.md`（同类数据按时间累积）的区别：那是「同类多条」，这是「一条案子分几层」。

## 触发

- 主档（README/汇总）已经长到几十 KB、既当结论又当日志，读的人找不到结论
- 案件横跨多天、多轮追问，堆出流程档、举报件、抓取件、他人报告一堆平铺文件
- 用户说「整理一下」「拆分」

## 目录形状

```
workspace/records/<YYYY-MM-DD-案件名>/
├── README.md        ← 总索引：导航表 ＋ 时间轴 ＋ 关键判据（不再当正文）
├── 00-判词/         ← 定稿结论（一页纸，带目录；改了要留修订记账）
├── 10-过程账/       ← 时间序全量日志 ＋ 原始记录（群聊、对谈原话）
├── 20-历史档/       ← 本案起点之前的旧档
├── 30-证件/         ← 对外要交的成品（材料包 ＋ 内部版 ＋ 对外版）
├── 40-取证/         ← 一手证据（抓取件 ＋ 逐文件 sha256 清单 ＋ 截图）
├── 50-机制附件/     ← 机制说明（流程步骤、链路明细）
└── 60-第三方核查/   ← 他人/同伴 AI 的报告只放**指针与结论**，原件留在其归属地
```

分层原则：**判词在前、过程账在后、证件与取证分家**；对外文本与内部备忘分开（对外版必须剥离内部备注与署名）。

## 四条硬规矩

1. **拆档只动位置与标题层级，正文一字不改**；拆出的档首写一行来历（「原为 README 第 X 节，YYYY-MM-DD 拆分」）。读者要能对上旧引用。
2. **拆完必跑 `bin/mdcheck <案件目录>` 到 0**：搬家必连带断链（相对深度、表格单元格里的裸文件名、生成物里的库外引用），修法见 `md-link-maintenance`。
3. **索引入口同步**：事件条目（`events/<案件>.md`）、总 INDEX、以及案件内部各档的交叉引用都要挂上新结构——只改目录里的文件＝断链。
4. **目录口径先摊给用户核对再归位**：整理/回填类活一律「确认在前、归纳在后」（先把要动哪些文件、怎么归并摆出来，点头才动手）；机械部分（编号归位、加目录、清临时物）可以顺手做，**改归属的部分等确认**。

## 收尾清单

- 判词档：编号连续、有目录、有附件清单（带相对路径）、文末有**时间轴 ＋ 盯点**
- 临时物：只清本案的中间产物（抓取缓存、原始页面）；**别的案子的文件一律不碰**
- 图片按仓库策略常被 gitignore ⇒ 不入 git，在索引里注明「仅本地」＋取证清单留 sha256
- **外来二进制样本（对方分发渠道取回的客户端 APK／录像／说明件）不进档案目录**：本体移 `workspace/quarantine/<YYYYMMDD>-<案>-样本/`（自带 README：清单＋哈希＋处置口径），根 `.gitignore` 加 `workspace/quarantine/`，**档案里只留哈希 ＋ 结论 ＋ 指针**；`git status` 里这类文件默认不受任何 ignore 保护（会以 `??` 裸奔），不处理就会被下一次 `git add` 拖进仓库。检查配方见 `source-code-investigation` 的 `source-code-investigation/references/apk-reversing.md` §外来样本
- 被第三方（同伴 AI/外部评审）报告带出的错判，反过来修自己档案时**留 ⚠️ 修正注**，不静默改（见 `record-integrity.md`）
