# 数据归档目录模式

当需要长期累积同一类数据项（存档文章、下载文件、日志记录等），使用这套目录结构。

## 结构模板

```
data-archive/
├── INDEX.md            # 全局索引（按关键时间戳倒序）
├── SOURCES.md          # 分类索引（按来源/类别分组）
├── 2026/
│   └── 07/
│       └── 2026-07-25_关键描述_来源.md
└── ...
```

## 原则

| 要素 | 说明 |
|:-----|:------|
| **目录分年/月** | 避免单个目录文件过多，按时间自然分片 |
| **文件名含时间戳** | 用内容的**原始时间**（发表时间/生成时间），非存档时间 |
| **文件名含来源+标题** | `{日期}_{标题}_{来源}.md`，一眼知道内容 |
| **YAML frontmatter** | 每文件头部的元数据（URL、时间、来源、标题等），方便脚本扫描 |
| **INDEX.md** | 按时间倒序排列的列表，每条包含日期+标题+路径+来源 |
| **分类索引** | 按来源/类别/标签分组，方便按维度查找 |
| **统计脚本** | `stats.py` 扫描全部元数据，输出来源频次、时间范围、分布 |

## 文件名规范

```
{YYYY-MM-DD}_{简短标题}_{来源}.{ext}
```

- 日期用数据本身的创建时间，非操作时间
- 标题截断到 60 字符，去非法字符
- 来源放在末尾，方便按来源排序时自动分组

## 索引文件格式

### INDEX.md — 时间序

```
- **2026-07-26** | [标题](相对路径) | 来源
- **2026-07-25** | [标题](相对路径) | 来源
```

### SOURCES.md — 分类序

```
## 来源A
  - **2026-07-26** | [标题](相对路径)

## 来源B
  - **2026-07-25** | [标题](相对路径)
```

## 适用场景

- 公众号文章存档（`wechat-article` skill 实现）
- B 站专栏/视频信息备份
- 每日新闻简报归档
- 任何需要「存了还能翻出来」的数据积累

## 要点

- 脚本一次性完成：下载/采集 → 提取元数据 → 写文件 → 更新索引 → 输出汇总
- 索引自动维护，不手动编辑
- 统计脚本随时可跑，不依赖持久化状态
- 整个目录可以 git 做版本管理和异地备份
