### E22 · 日记收尾三件 + 工具体检边界（2026-09-11）

22. **日记收尾三件 + 工具体检边界（2026-09-11）** — 写日记（`diary/daily-YYYY-MM-DD.md`）不是写完正文就算完，收尾三件一次做齐：① 正文落盘（当天追加用 `patch`，不覆盖）；② `diary/INDEX.md` 表格**顶部倒序插一行**`| 日期 | [标题](daily-YYYY-MM-DD.md) | 摘要 | 时间 |`，**顺手回看上一行在不在**（2026-09-11 实测：09-10 正文写了、INDEX 漏挂——纪律会滑）；③ `git add` 只加这两个文件（勿 `-A`）。⚠️ **`diary.py check`／`stats` 只扫 `<记忆目录>/YYYY-MM-DD.md`（memory 笔记模板），不校验 `diary/daily-*.md`**——它报「0 sections」之类跟日记正文无关，别当体检结果；日记结构按 日记类 skill（作者环境，未单独公开） `references/01-rules.md` 的人工核。注：日记类 skill（作者环境，未单独公开） 为用户自有 skill（自动改会被拒），本条暂存这里；建议 `hermes curator adopt 日记类 skill（作者环境，未单独公开）` 后回迁。


### E24 · 登记类 CLI 的参数陷阱 + 视频/链接类登记配方（2026-09-11 星夜

24. **登记类 CLI 的参数陷阱 + 视频/链接类登记配方（2026-09-11 星夜颂歌实例）** — 用户甩链接说「登记下」时的四个点：① **`ro add --sources` 只用 `|` 分隔，绝不能传换行**——`add_entry` 按 `|` split，传换行就把整串当一个源：条目文件的来源列表**只有第一行带 `- ` 前缀**，INDEX 那行还会被拆成多行、破坏「一条一行」的索引格式（`_insert_index_line` 是逐行插入的）。已写坏就事后 patch 补 `- ` + 把换行换成 `；`。② **整段中文参数走 `subprocess.run([...])` 列表传**（在 `execute_code` 里调 `scripts/ro.py`），别用 shell 单引号拼含「」/括号/`**` 的长中文。③ **`ro done` 的 git add 范围写死**（`skills/记录类 skill（作者环境）/` + `diary/` + `<记忆目录>/`），不是 `-A`，推送走后台 Popen 不等待——**别自己再 `git add -A`**。④ **登记配方**：先 `grep -rl "<产品名>" <项目目录>/ skills/` 定有无档案（有→后续补充，无→新建，同产品不重复建）；用工具拉详情别手抄（B站走 `bilibili-api-ops`，注意 `bili_video_info.py` 的简介会截断到 ~100 字，要全文改走裸 `view` 接口读 `data.desc`）；用户点名「重点在简介」时**简介即正文主体**（事件段按 ①②③ 逐条落要点，末尾接产品自我定位）；厂商自述（「超人格化」这类话术）与商店页/官网实测（发售日/开发商/语言——事实）分栏；官方视频简介 + 官方商店页两源即可定 ✅真，不必凑二手。注：记录类 skill（作者环境） 为用户自有 skill（自动改被拒），本条暂存这里；建议 `hermes curator adopt 记录类 skill（作者环境）` 后回迁。
